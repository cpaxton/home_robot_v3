\section{Multi-room agent-task preflight}
\label{app:agent_task_preflight}

We introduce three small multi-room cases for validating the agent interface and
evaluation machinery before larger experiments: cross-room delivery, two-object
collection, and a moved-object revisit. A deterministic three-room MuJoCo fixture
uses the packaged rby1 geometry, open placement trays, and a fixed scene seed.
Success requires each target's measured center to lie within its specified XYZ
placement region and the object not to be held. Negative controls include no
action, incorrect destinations, partial completion, and stale plans.

The initial controls invoke the existing CHAT planning/execution tool registry
with ground-truth object geometry, synthetic grasps, footprint-checked kinematic
navigation, and object-pose teleportation. Rendering uses forward kinematics and
a recorded fixture-only downward head-camera mount. These controls establish
repeatable assisted execution and evaluator behavior; they do not establish
contact-stable manipulation, learned perception, agent planning, or memory
recovery. The moved-object witness has privileged knowledge of the relocation.
Multi-room live ZMQ and full learned-memory integration are separate acceptance gates.

Recorded events separate policy-visible state from private evaluator truth and
link tool outcomes, observations, trajectories, and goal predicates. Offline
exports produce synchronized replay, video, and figures from the same evidence.
Absent learned memory is explicitly marked as unrecorded rather than reconstructed
from ground truth. The initial release makes no paid model calls.

\subsection{Local-policy task interface}
The next preflight stage runs a cached local language model through the shared
agent's bounded task mode, also exposed by \texttt{run\_agent.py}. This mode
preserves conversation history across decisions and continues after tool results.
The environment provides bounded camera-based room search, navigation, and either
combined pick-and-place or separate plan/execution calls. All manipulation still
uses the shared guarded planning and execution implementation with the assistance
profile described above.

Three layouts are available: the original three-room fixture, a three-room layout
with extra furniture, and a four-room layout including a study. Object recognition
is assisted: labels and positions enter the observation cache only when the
corresponding object has pixels in the rendered head-camera segmentation. Hidden
world changes leave cached observations unchanged until a later observation.
This cache is not the learned voxel/semantic-graph backend. Policy prompts,
responses, syntax repairs, command outcomes and historical cache contents are
recorded separately from evaluator truth.
