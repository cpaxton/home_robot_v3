\begin{abstract}
Embodied question answering (EQA) requires a robot to explore an unknown environment, build a semantic model of what it sees, and answer natural-language questions with sufficient confidence to know when to keep looking.
We present \textbf{Dynagraph}, which keeps \textbf{DynaMem's voxel update rules} and adds \textbf{GraphEQA graph-creation steps} on the same perception stream.
Each voxel records when it was last seen and a pointer to the supporting observation (pose, robot configuration, images); object-centric graphs are \textbf{grounded in this map}, so the system can detect when an object is \textbf{no longer observed} and retire stale hypotheses.
Dynagraph adds \textbf{spatial merge} and \textbf{staleness pruning} so memory stays compact and current as the robot moves and the scene changes.
We implement Dynagraph in the open-source \texttt{emet} stack (\texttt{emet run dynagraph}) and evaluate on \textbf{Habitat} (HM-EQA and OpenEQA-style benchmarks, via a dedicated harness) and on \textbf{MuJoCo simulation} (Robocasa kitchens, MolmoSpaces iTHOR, multiple robot embodiments).
On a preliminary HM-EQA slice with \texttt{Qwen3-VL-8B-Instruct}, Dynagraph corrects the previously failing Q17 search question after phrase-level grounding and location-MCQ prompting, and scores \textbf{4/8} (50\%) on a held-out random subset that excludes tuning ids---above 25\% chance but below GraphEQA API baselines; that slice predates July 2026 Image-$N$ navigation waypoints, and the full 113-question sweep with the complete fix stack remains in progress.
We additionally compare a \textbf{classic} GraphEQA planning loop to an optional \textbf{agentic} tool controller on the same Dynagraph memory (retrieve place evidence cards, navigate / explore, detector proposals, VLM assess / submit): on the anti-overfit holdout-8, agentic reaches \textbf{8/8} vs.\ classic \textbf{5/8} with roughly $3\times$ fewer planning steps; on balanced-32 the letter edge is small and not significant, while the planning-step reduction remains large.
Other benchmark tables (OVMM find-phase, SQA3D, dynamic exploration) are pending large-scale sim runs.
\end{abstract}
