\textit{Experimental results are pending. This section records the evaluation plan.}

\subsection{Goals}

\begin{enumerate}
  \item \textbf{Habitat EQA (primary):} Reproduce GraphEQA-style metrics on HM-EQA (113 questions) and an OpenEQA subset: success rate, mean planning steps, GraphEQA vs.\ Dynagraph vs.\ ablations (parity checklist and official baselines: Appendix~\ref{app:habitat_eqa_parity}).
  \item \textbf{SQA3D situated open QA:} Embodied ScanNet replay with EM@1 scoring (Section~\ref{sec:sqa3d_benchmark}); compare \texttt{dynamem} vs.\ \texttt{dynagraph} with \texttt{prompt\_variant: sqa3d}.
  \item \textbf{OVMM-inspired find-phase:} FindObj / FindRec localization on Emet sim tiers S0--S2 and Habitat HM3D proxy episodes (Section~\ref{sec:ovmm_find_phase}); memory backends \texttt{dynamem}, \texttt{graph\_eqa}, \texttt{dynagraph}, and sim oracle \texttt{ground\_truth}.
  \item \textbf{Emet sim (complementary):} Robocasa kitchens and MolmoSpaces iTHOR with Stretch, Galaxea R1 (rby1), and Innate Mars (Appendix~\ref{app:innate_mars}); depth-source policy in Appendix~\ref{app:da3}; GT-supervised object finding (Section~\ref{sec:gt_experiments}).
  \item \textbf{Dynamic episodes:} After object relocation, measure stale nodes, wrong answers, and recovery steps (Dynagraph vs.\ GraphEQA without staleness).
\end{enumerate}

\subsection{Methods compared}

Shared backend names (\texttt{src/emet/eval/memory\_backends.py}):

\begin{itemize}
  \item \textbf{\texttt{dynamem}:} voxel semantic memory (+ optional EQA on SQA3D); no graph merge/staleness.
  \item \textbf{\texttt{graph\_eqa}:} voxel + graph; merge and staleness disabled (\texttt{emet run graph-eqa}; OVMM baseline row).
  \item \textbf{\texttt{dynagraph}:} voxel + graph with merge/staleness; profile chosen per harness (below; \texttt{emet run dynagraph}).
  \item \textbf{\texttt{ground\_truth}:} sim oracle graph from \texttt{sim\_object\_placements} (OVMM / GT finding upper bound).
  \item \textbf{Ablations:} \texttt{--merge-xy-m} / \texttt{--staleness-horizon} overrides; HM-EQA \textbf{frontier policy} (fluid voxel sampler vs.\ graph frontier nodes; Appendix~\ref{app:habitat_eqa_parity}); OK-Robot-style static prescanned map (optional).
  \item \textbf{DynaMem voxel-only EQA} and \textbf{VLM-only} baselines where applicable.
\end{itemize}

\textbf{Dynagraph profiles.}
Merge, staleness, and short-episode caps are centralized in \texttt{configs/benchmarks/dynagraph.yaml} (\texttt{emet.eval.benchmark\_dynagraph}); \texttt{dynav\_config.yaml} matches the \texttt{interactive} profile (\texttt{emet run dynagraph}).

\subsection{GT-supervised object finding (Emet sim)}
\label{sec:gt_experiments}

\textit{Results pending.}
MuJoCo ZMQ servers publish \texttt{sim\_object\_placements} in \texttt{emet\_session}: per-body semantic labels, world positions, and (when scanned) axis-aligned bounds.
\texttt{emet run dynagraph --ground-truth} seeds graph nodes from this metadata while Stage~1 voxel fusion, rotate-in-place, and frame logging continue unchanged---inverting the usual perception$\rightarrow$graph flow so sim supplies authoritative labels and the voxel map supplies sensor evidence.
This supports reproducible object-finding benchmarks and labeled episode export for fine-tuning without a Habitat harness (Appendix~\ref{app:ground_truth_graph}).

We evaluate whether Dynagraph memory can \textbf{find objects whose labels and positions are known from simulation}.
Robocasa kitchens (multiple layout/style seeds) and the default table scene serve as episodes; Stretch is the primary robot, with spot checks on rby1 and Innate Mars via the same \texttt{emet\_session} contract.

\textbf{Modes.}
\texttt{--ground-truth} uses sim metadata as the graph; \texttt{--compare-to-gt} runs full perception and reports alignment vs.\ GT (Rerun overlay + text report).

\textbf{Metrics} (oracle = \texttt{sim\_object\_placements}):
\begin{itemize}
  \item \textbf{GT graph completeness:} fraction of placement bodies present as GT graph nodes at startup.
  \item \textbf{Localization error:} for each manipulable body, query the graph by \texttt{cat} and report XY (and optionally Z) error vs.\ GT \texttt{pos}.
  \item \textbf{Instance$\rightarrow$GT association recall:} fraction of GT bodies matched by a YOLO-E instance centroid within 0.75\,m XY after rotate-in-place (and optional explore steps).
  \item \textbf{Perception$\rightarrow$GT recall @\,$r$:} under \texttt{--compare-to-gt}, fraction of GT bodies with a non-GT graph node within $r$\,m (label match optional).
  \item \textbf{Projected association IoU:} overlap between GT AABB projected into the head camera and the best-matching instance mask per frame.
\end{itemize}

\textbf{Protocol.}
\begin{enumerate}
  \item \texttt{emet serve mujoco --scene robocasa --headless --port-offset N} (or default table / MolmoSpaces).
  \item \texttt{emet run dynagraph --ground-truth --export runs/<episode\_id> --port-offset N} (rotate-in-place by default; exports graph + voxel frames + GT sidecars).
  \item Batch: \texttt{uv run python scripts/eval\_dynagraph\_ground\_truth.py --run-live --port-offset N --output metrics.json}.
  \item Compare perception: \texttt{emet run dynagraph --compare-to-gt --export runs/<id> -N}.
\end{enumerate}

See \texttt{docs/paper\_benchmarks.md} and Appendix~\ref{app:ground_truth_graph}.

\subsection{SQA3D situated open QA (ScanNet replay)}
\label{sec:sqa3d_benchmark}

\textit{Results pending.}
SQA3D~\cite{sqa3d2023} evaluates \emph{situated} open-ended QA: each sample fixes agent pose in a ScanNet scene and asks a free-form question about the surroundings.
We report \textbf{EM@1} after the official answer normalization protocol (LEO / LLaVA-3D style), not multiple-choice accuracy.

\textbf{Memory backends:} \texttt{dynamem}, \texttt{dynagraph} (default, \texttt{eqa} profile in Table~\ref{tab:dynagraph_profiles}).
EQA uses \texttt{prompt\_variant: sqa3d} and real VLM graph labeling; mock-LLM smoke uses the \texttt{smoke} profile (merge off).

\textbf{Replay.}
Posed ScanNet \texttt{.sens} RGB-D when available (\texttt{--replay-mode sens}); otherwise Open3D mesh rendering over \texttt{\_vh\_clean\_2.ply}.
\texttt{auto} falls back to mesh when the agent leaves the SQA3D anchor neighborhood or when the nearest sens frame exceeds 0.75\,m XY.
Episode JSONL logs \texttt{replay\_backend}, \texttt{sens\_match\_xy\_m}, and \texttt{infra\_failure} for figure breakdowns (TP/FP/FN/infra).

\textbf{Protocol.}
\begin{enumerate}
  \item Data: \texttt{scripts/download\_sqa3d\_data.py --fetch-annotations}; ScanNet meshes + optional \texttt{.sens} via \texttt{scripts/download\_scannet\_data.py --with-sens}.
  \item Smoke: \texttt{emet sqa3d run-episode --mock-llm --question-id <id>}.
  \item Real-VLM batch: \texttt{emet sqa3d run-real-sweep --split val --replay-mode sens --isolate-episodes} (defaults in \texttt{configs/sqa3d/benchmark.yaml}; GPU notes in \texttt{docs/sqa3d\_compute.md}).
  \item Score / figures: \texttt{emet eval-sqa3d -p <batch>.jsonl}; \texttt{emet sqa3d plot-results -p <batch>.jsonl -o figs/}.
  \item Aggregate: \texttt{scripts/aggregate\_sqa3d\_sweep.py} $\rightarrow$ \texttt{aggregate\_sqa3d.csv} for Table~\ref{tab:sqa3d_backend_replay}.
\end{enumerate}

\textbf{Metrics.}
EM@1, EM@1 refined (diagnostic), mean planning steps, TP/FP/FN/infra outcome counts, optional per-question-type breakdown.
\textbf{Not comparable} to OVMM find-phase partial success (language answers vs.\ object/receptacle localization).

See \texttt{docs/sqa3d.md} and \texttt{docs/paper\_benchmarks.md}.

\subsection{OVMM-inspired find-phase localization}
\label{sec:ovmm_find_phase}

\textit{Results pending.}
Following OVMM~\cite{ovmm2023}, each episode specifies ``move \emph{object} from \emph{start\_recep} to \emph{goal\_recep}.''
Full OVMM scores four phases (FindObj, Pick, FindRec, Place); we ablate only the memory-dependent localization legs:
\textbf{FindObj} (where is the manipulable object, disambiguated using the start receptacle) and
\textbf{FindRec} (where is a body matching the goal receptacle category).
Pick, place, gaze, and reactive navigation loops are out of scope.

\textbf{Map-then-query (not pure memory).}
All backends share a fixed \emph{mapping} protocol before any find-phase query:
rotate-in-place (8$\times$45° with per-step \texttt{update()}, unless \texttt{--not-rotate}) plus optional frontier \texttt{explore\_steps} via \texttt{execute\_action("")}.
Only then does the harness query memory---it does not interleave further exploration with FindObj/FindRec.
Fair-default sim runs use instance detections on voxel frames without per-frame VLM labeling (\texttt{use\_sensor\_perception=false}); queries default to \textbf{voxel-first} (\texttt{prefer\_voxel=true}).

\textbf{Emet sim ladder.}
Episodes in \texttt{configs/ovmm/find\_phase\_episodes.yaml}: tiers S0 (default table), S1 (Robocasa), S2 (MolmoSpaces iTHOR indices 0--2).
GT oracles read \texttt{sim\_object\_placements}: FindObj compares predicted XYZ to the chosen object body (nearest match to \texttt{start\_recep} when multiple bodies share a category); FindRec compares to the nearest GT body matching \texttt{goal\_recep}.
Success radius $r$ is \textbf{tiered} (not one global 0.75\,m): S0 $r{=}0.30$\,m, S1 $r{=}0.50$\,m, S2 $r{=}0.75$\,m.
We report \textbf{localization error} (m) as the primary localization metric; binary success and \textbf{partial success} (mean of FindObj and FindRec @\,$r$) are secondary.
Pilot S0 fair-default runs (rotate only, voxel path) yield $\sim$0.08\,m object XY error for both \texttt{dynamem} and \texttt{dynagraph}---well inside S0 $r$.

\textbf{Protocol (sim).}
\begin{enumerate}
  \item Smoke: \texttt{uv run python scripts/smoke\_ovmm\_benchmark.py --cpu-only}.
  \item Batch: \texttt{uv run python scripts/eval\_ovmm\_find\_phases.py --tier S0 --backend dynamem --backend graph\_eqa --backend dynagraph --backend ground\_truth}.
  \item Mapping fixed per episode; only memory backend and Dynagraph profile vary (\texttt{find\_phase} / \texttt{graph\_eqa\_baseline} in Table~\ref{tab:dynagraph_profiles}).
  \item Do \textbf{not} pass \texttt{--not-rotate} for perception backends; oracle may use \texttt{--backend ground\_truth --not-rotate --cpu-only}.
  \item Aggregate CSV: \texttt{aggregate\_<backends>.csv} in output dir $\rightarrow$ Table~\ref{tab:ovmm_find_backend_tier}.
\end{enumerate}

\textbf{Protocol (Habitat proxy).}
\begin{enumerate}
  \item Episodes: \texttt{configs/ovmm/habitat\_find\_phase\_episodes.yaml} (HM3D train scenes; $r{=}0.75$\,m).
  \item Batch: \texttt{uv run python scripts/eval\_habitat\_ovmm\_find\_phases.py --backend ground\_truth --cpu-only}.
  \item Full OVMM-HSSD minival not wired; HM3D proxy validates Habitat memory $\rightarrow$ find-phase metrics before HSSD download.
\end{enumerate}

\textbf{Metrics.}
\texttt{localization\_err\_obj\_m}, \texttt{localization\_err\_recep\_m}, FindObj/FindRec success, partial success, \texttt{obj\_localize\_source} / \texttt{recep\_localize\_source}, graph node count, voxel explored area (m$^2$), wall time, \texttt{n\_placements}.
See \texttt{docs/ovmm\_find\_phase\_benchmark.md} and \texttt{docs/paper\_benchmarks.md}.

\subsection{Scaling to large scenes}
\label{sec:scaling_large_scenes}

\textit{Results pending.}
Designed to stress-test Dynagraph node growth and exploration budget on S0$\rightarrow$S2:

\begin{itemize}
  \item \textbf{Scene-size sweep:} success and \texttt{n\_graph\_nodes} vs tier and Molmo index (Fig.~\ref{fig:ovmm_scaling_success}, Fig.~\ref{fig:ovmm_scaling_nodes}).
  \item \textbf{Exploration budget:} \texttt{explore\_steps} $\in \{0, 5, 15, 30\}$ on S2 index 0.
  \item \textbf{Merge / staleness grid:} \texttt{--merge-xy-m} $\in \{0, 0.15, 0.25, 0.45, 0.75\}$, \texttt{--staleness-horizon} $\in \{0, 128, 256, 512\}$ on S2 (default batch uses \texttt{find\_phase} profile: 0.15\,m merge).
\end{itemize}

\textbf{Known limits.}
Molmo GT fixture scans may cap on large scenes; Robocasa layout $\neq$ HSSD; static placements (no mid-episode object move in Phase~1).
