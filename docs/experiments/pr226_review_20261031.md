## History call-site audit

- `AbstractVLLMClient.generate_messages()` explicitly continues an isolated
  supplied dialogue inside `preserve_conversation()`.
- CHAT's initial inference uses `reset_context=not followup_round`; tool
  follow-ups and final summarization intentionally continue the current turn.
- Interactive `app/chat.py` advertises history-on multi-turn chat, while its
  single-turn path explicitly resets.
- `dynamem_vllm_call()` explicitly uses `reset_context=True`; ordinary perception
  does not silently opt into replay. No unintended continuation caller was found
  in the checked-out first-party code. This is not a downstream-caller guarantee.

Shared clients and conversation preservation do not provide concurrent inference
isolation. Callers must serialize operations or use separate clients. Metrics
remain per-instance latest-call data, not per-call concurrent receipts. Added
`request_image_count` alongside the existing current-turn `image_count`, so traces
can expose retransmitted image payloads rather than undercount them.

## Camera derivation

Raw registration uses OpenCV optical axes (right, down, forward). Clockwise raster
rotation maps `u' = H - 1 - v`, `v' = u`; the published optical coordinates become
`X' = -Y`, `Y' = X`, `Z' = Z`. Substitution in the pinhole equations gives
`fx' = fy`, `fy' = fx`, `cx' = H - 1 - cy`, `cy' = cx`, matching `head_K`.
The camera manager registers raw depth into raw RGB before that raster rotation.
The producer's upright pose applies the corresponding optical-frame rotation.
The new check unprojects the same registered sample before and after actual
`np.rot90(..., k=-1)`, using the producer's poses, and requires equal world points.
